# Vietcong Docker Container

This Docker container runs a Vietcong (2003) dedicated server. It is built on the WINE image and runs the retail v1.60 dedicated server launcher, `vcded.exe -dedicated <file>.ded`, under Wine and Xvfb. The container doesn't download the game, so you provide the files.

## Quick Start

```yaml
services:
  vietcong:
    image: lancommander/vietcong:latest
    container_name: vietcong

    ports:
      - 5425:5425/udp
      - 6073:6073/udp

    volumes:
      - "/data/Servers/Vietcong/Deathmatch:/config"

    environment:
      VC_SERVER_NAME: "My Vietcong Server"
      VC_ADMIN_PASSWORD: "changeme"

    user: root
    cap_add:
      - SYS_ADMIN
    security_opt:
      - apparmor:unconfined

    restart: unless-stopped
```

Copy a Vietcong **v1.60** install (the folder with `vcded.exe`, `game.dll`, `logs.dll` and the `vietcong_*.cbf` archives) into `Server/` before the first start. You can instead set `VC_ARCHIVE_URL` to a zip of that folder.

## How It Starts

1. `PostInitialization/10-InitializeWinePrefix.ps1` (from the WINE image) creates the Wine prefix in `/config/wineprefix`.
2. `PostInitializeWinePrefix/20-InstallDirectPlay.ps1` runs `winetricks directplay` once, using the DirectX redist cached in the image. This installs Microsoft's `dpnet.dll` and related DLLs. Vietcong hosts with DirectPlay 8, and Wine's builtin `dpnet` can't host. A marker file, `wineprefix/.lancommander-directplay`, records that the install is done. Delete it to reinstall.
3. `PostInitialization/20-InstallVietcong.ps1` checks for `Server/vcded.exe`. If it's missing and `VC_ARCHIVE_URL` is set, the hook downloads the archive.
4. `PostInitialization/30-ConfigureVietcong.ps1` writes `Dedicated/<VC_DED_NAME>.ded` from the `VC_*` variables (it lands in `Overlay/Dedicated/`).
5. `START_EXE` (`/usr/local/bin/vc-server`) runs `wine-run vcded.exe [-addon <VC_ADDON>] -dedicated <VC_DED_NAME>.ded` from the game root and follows `dev/chatlog.txt` to stdout.

`vcded.exe` is a GUI program. Without `-dedicated` it opens the setup dialog (map list, settings, Save/Start). With `-dedicated` it hosts at once and shows a small status window ("Server info", players, "Exit the game") on the Xvfb display. It writes nothing to stdout. A successful start looks like:

```
Starting: vcded.exe -dedicated lancommander.ded
2026-11-02 06:03:04.485 - === Loading map : WaterFallDM ===
```

## Configuration Options

### Ports

- **5425/udp**: Game (DirectPlay host, `VC_PORT`). It also answers DirectPlay enumeration.
- **6073/udp**: DirectPlay enumeration (`dpnsvr`). The in-game LAN list uses it.

DirectPlay also opens a few dynamic UDP ports. Giving the container its own LAN address (macvlan/ipvlan) is the most reliable setup. The server binds per interface, so query it on the container's LAN IP rather than 127.0.0.1.

With `VC_INTERNET_GAME=true` the server also registers with the master server (the bundled `logs.dll` from VCStarter points at OpenSpy). The community lists UDP 15425 as the query port for that. LAN play doesn't need it.

### Hooks

| Hook | When |
|------|------|
| `PreInstallVietcong` / `PostInstallVietcong` | Around the game file check/download |
| `PreInitializeWinePrefix` / `PostInitializeWinePrefix` | Around Wine prefix creation (WINE image) |

Put `.ps1` scripts in `config/Scripts/Hooks/<HookName>/`.

## Troubleshooting

- **The server runs but UDP 5425 is never bound.** vcded found a problem in the `.ded` file. It shows a message box ("Can't find map "X" at line N", "Error loading definition file") and waits forever, which you can't see in a container. The configure hook checks base-game maps and modes before starting. A map from an add-on or user map is only warned about, so check its exact name and modes in vcded's setup dialog. If the hook rejects `VC_MISSIONS`, it logs the reason and the previous `.ded` stays in place.
- **Edits to `Overlay/` from the host while the container runs don't show up.** OverlayFS caches the upper directory. Restart the container, or edit through `Merged/` inside it (`docker exec`).
- **Clients can't join.** They need v1.60 (`gamever 198`). A HradBa server rejects VCStarter clients, so keep `VC_HRADBA=false` unless every client runs HradBa.
- ALSA "cannot find card" messages in the log are harmless; the server needs no sound device.
- Idle CPU is about 20% of a core (vcded's window loop under Xvfb).
